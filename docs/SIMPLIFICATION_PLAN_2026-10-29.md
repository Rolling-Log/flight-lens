# 航探精简与全价搜索工作计划

航探下一阶段只围绕一个结果推进：在用户给定的日期、机场、人数、行李和资格条件下，找到更便宜、能够在来源页面核实的机票产品。优先完成个人本机找票助手，再评估公开服务。Ego Lite 作为本机浏览器执行工具试点接入，价格规则继续由现有确定性代码负责。

当前最需要改变的是验收目标与搜索流程。返回更多列表报价、增加来源徽标、登录成功或测试通过，都不足以证明找到了更便宜的可购买产品。

## 从目标推导最小流程

完整流程应为：确定条件 → 发现候选 → 展开具体产品 → 核验全价与资格 → 按可比较全价排序 → 回到同一产品复核。

全价包含票面价、机建、燃油和无法取消的必选费用；用户确实满足条件且当次可使用的优惠才可扣减。行李要求、退改条件、购票人数和付款渠道可能改变可比较范围。机建燃油不能套用一组永久常量，多人报价也不能仅以单人最低价乘人数代替库存核验。

“当前覆盖范围内已核验的最低价”是可验收结果。全网最低还要求掌握 App 专属产品、会员券、航司直销及所有有效渠道；没有访问到的渠道必须列为覆盖缺口，不能用其他平台报价代替。

接入分两步。第一步只让 Agent 在 Ego 中完成候选与费用核验，输出结构化的本地结果和必要证据，用现有规则校验。先不增加常驻服务。第二步在试点通过后，给现有搜索任务增加一个薄的 Ego 执行适配器；网页仍负责条件、结果和进度。Netlify 页面不能凭空启动用户电脑上的 Ego，若要从网页一键触发，需要单独解决本机连接和访问范围。

Ego 可以减少反复连接扩展、人工盯住标签页和探索页面步骤的成本，但不会新增机票库存、授予 App 权限，也不会保证平台不要求登录或验证码。已有 Edge 登录态不应假定自动可用；安装后只处理需要的站点登录。Windows 目前为 beta，官方更新记录仍在修复崩溃，因此是否替换现有入口必须依靠实测。[Windows 快速开始](https://www.egolite.ai/document/en/docs/windows/quick-start)、[更新记录](https://www.egolite.ai/changelog)

浏览器读取的原文是证据，模型负责识别页面和提出动作，金额计算、条件匹配、证据升级与排序由代码执行。不要把模型一句“已含税”直接写成核验通过；不要因为读取到结构化响应就认定最终支付价。

### 第一阶段 建立本机核验基线

- [x] 安装已下载的 Ego，确认浏览器与官方 `ego-browser` 工具已生成。
- [x] 完成首次设置与必要站点登录，确认工具能读取页面、展开产品并保存出处。登录、验证码由用户在站点完成。
- [x] 先跑 1 条航线、2 个可访问来源、每源 3 个候选；止于费用可见的产品或填写页面，不提交订单。2026-10-30 完成携程、同程各 3 个候选，详见下方实测。
- [ ] 将同一任务在 Edge 与 Ego 各跑一遍，记录失败环节、人工接管次数、候选全价、耗时和模型消耗。
- [ ] 小样本成功后扩至 PEK → SHA、CGO → SYX、CAN → URC，各取执行日后 7 天和 30 天。优先携程、同程及有可访问入口的航司官网；不可访问来源如实标记。

完成标准：报价身份、机场、日期、人数和费用均能与原页面逐项对照；错误升格为“已核验”必须为零。6 个场景至少 5 个完成主要核验流程，失败原因可定位。此门槛用于决定是否继续试点，不能据此宣称全网覆盖或长期成功率。

对照应使用相同资格与条件，先确认两种浏览器的登录状态可比，在尽可能接近的时间复核。价格变化时重新读取来源，不把时间差造成的变价归因于浏览器效果。若 Ego 没有改善完成率、接管成本或诊断能力，则保留它作为调试工具，不迁移主流程。

### 由实测决定的下一步

1. **先改变发现单位。** 航班卡片用于发现候选，不是最终商品。同程 MU5102、CA1527 都证明：列表资格价不适用时，仍需展开同航班的其他产品。不能只把已有资格过滤放松，否则会把真实限制票误排到第一。
2. **建立产品观察的最小契约。** 在既有 contracts / Offer 上增加具体产品、供应商、适用资格、人数、证据阶段和观察时间的关联；保留“列表价”“费用组成”“填写页总额”三个不同层级。沿用现有金额与排序逻辑，不建立第二套价格系统。填写页总额不自动意味着个人资格、付款渠道和最终出票均已核验。
3. **先实现一个小而完整的本机闭环。** 携程、同程分别完成发现 → 展开 → 选择无额外服务产品 → 读取费用 → 校验身份与金额 → 输出。人工登录集中完成；页面接管后暂停，收到继续再恢复；真实密码和证件只留在站点。先让 Agent 用 Ego 执行这一流程，不增加常驻桥接服务。
4. **将永久入口问题从重试队列移出。** 记录实际 URL 与预期页面不符，报告“入口不可用，未覆盖”；不要改成空结果或反复提示登录。去哪儿移动端或官方合作渠道另做独立可行性检查，不通过修改 UA、反复重试旧页来宣称解决。
5. **完成对照再决定迁移。** 下一次同条件运行 Edge / Ego；随后跑三航线的 D+7、D+30。记录完成率、产品漏检、接管次数、耗时和实际成本。本轮只能证明 Ego 能完成这批流程，不能证明其比 Edge 更可靠，模型消耗尚未取得可比较统计。

这轮没有将浏览器试点接入网站或发布 Netlify；网站仍需上述契约与执行闭环后才能展示这类产品全价。六个候选中最低的填写页显示总额为 740 元，这只是本次已检查样本中的最低值，不是全网最低结论。
