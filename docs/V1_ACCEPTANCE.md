# V1 验收门禁

V1 的目标不是证明“能显示航班”，而是证明系统能稳定、透明地比较至少两个合法实时来源，并把用户交接到可继续购买的来源页面。

| 全价口径 | 币种、税费、必需费用、行李、资格条件和未知项可见 | 契约、领域测试与 SerpApi Staging 响应已通过；行李与退改未知项未伪造 |

任何硬门禁未通过时，只能称为 V1 开发版或候选版，不能称为正式 V1。

## Staging 验收样本

至少执行以下受控查询，并记录检索时间、来源状态、最低可比价、实际售卖方、跳转类型以及落地页复核结果：

1. 中国内地国内单程：上海 → 北京；
2. 中国出发国际往返：上海 → 东京；
3. 中国到达国际单程：新加坡 → 广州；
4. 同城多机场：北京 → 上海；
5. 跨日或红眼航班；
6. 带托运行李、限预算、限中转条件；
7. 单个 Connector 故障与全部 Connector 故障；
8. 缓存命中和 stale-if-error 降级。

真实供应商测试应控制调用量；不得把本地密钥、响应中的供应商 Token 或个人信息写入仓库和验收报告。

## 版本确认顺序

1. 在功能分支完成代码与自动化校验；
2. 合并到 `develop`，创建隔离 Staging；
3. 完成真实来源、跳转、数据库审计和回滚验证；
4. 向用户提交 V1 候选报告；
5. 仅在用户明确确认后，合并 `main`、创建 `v1.0.0` Tag、推送正式版本并部署 Production。
